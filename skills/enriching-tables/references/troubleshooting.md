# 故障排除

根据症状选择对应修复方法。不要原样重新运行失败的命令，应先诊断问题。退出代码：`2` = 用法/配置错误（你的错误，可免费修复），`1` = 运行时错误，`130` = 已中断（可恢复）。

## “错误：缺少凭据”（退出代码 2）

四项凭据中有一项或多项无法从环境变量、工作目录中的 `.env` 或已存储登录配置中解析。错误会为每个变量输出一行 `✓`/`✗`，请修复标记为 `✗` 的变量。

- 设置缺失的环境变量，**或者**运行 `enrich login` 并填写。
- 请记住解析顺序：真实环境变量 > `.env` > 已存储配置。如果过期的环境变量覆盖了已存储配置，请取消设置该变量。
- 首次设置：`references/onboarding.md`。

## 在 `enrich login` 期间出现“API 密钥无效”

`login` 会在保存前进行实时验证。`✗ Bright Data: invalid API key` 或 `✗ OpenRouter: invalid API key` 表示密钥错误或已撤销，请在相应控制面板中重新生成并输入。只有两者都通过验证后才会保存。

## “无法自动检测标识符列”（退出代码 1）

CLI 无法判断哪个列用于标识每一行。请明确指定：

```bash
--column <the_column_with_domains_or_emails>
```

域名/网站列最容易被自动检测；自由文本名称列最难。

## “未知字段名称：...” （退出代码 2）

`--fields` 中的某个名称不是预设字段。错误会列出有效名称，请从 `references/fields.md` 中准确复制，或改用不要求精确名称的 `--describe "<plain english>"`。

## “错误：--describe 与 --fields 互斥”（退出代码 2）

只能传入其中一个，绝不能同时传入。

## “文件存在但列不兼容”/标头不匹配（退出代码 1）

输出文件已存在，但其标头与本次运行将生成的列不匹配，这通常是因为你在两次运行之间更改了 `--describe`/`--fields`，导致无法安全恢复。

- 要**继续**上一次运行：使用与之前**相同**的 `--describe`/`--fields`。
- 要**重新开始**：传入 `--no-resume`（覆盖），选择新的 `-o` 输出路径，或删除旧文件。

## 运行被中断（Ctrl-C、崩溃）：退出代码 130

只需重新运行**完全相同的命令**。恢复会自动进行：它读取现有输出的标头，并跳过已写入的行。仅当字段集完全相同时才有效，因此不要更改 `--describe`/`--fields`。

## 单元格返回空值

空值很正常，表示智能体找不到该实体的相应事实（例如私营公司的收入，或个人的直拨电话；后者仅在明确找到时填写）。这不是错误。要提高命中率：

- 提供更好的标识符：**域名**优于公司名称；对于人员，请提供 `--first-name`/`--last-name`。
- 确保该实体确实能在公开网页上找到。

## 速率限制/速度慢/不稳定

- 调低 `--concurrency`（默认值为 30）以减轻压力：`--concurrency 5`。
- 在控制面板中检查 Bright Data 区域状态和账户预算。
- 对于超大型文件，请分批运行；停止后重新运行即可（会自动恢复）。

## “无法从描述中解析任何字段”（退出代码 1）

`--describe` 文本过于模糊，无法映射或生成字段。请写得更具体（“员工人数、融资阶段、CEO 姓名”），或改用明确的 `--fields`。

## 运行期间 stderr 输出嘈杂（警告、“Snapshot not ready”、MaxListeners）

`[crunchbase] Snapshot not ready (attempt N/60)`、`unexpected API response shape` 或 Node `MaxListenersExceededWarning` 等行是引擎输出到 stderr 的内部进度/诊断信息。它们**并不**表示失败；只有某一行的最终结果显示 `✗ error` 时，该行才算失败。最终结果以结束摘要（`N done • N skipped • N errors`）和写入的 CSV 为准。某个抓取工具来源（例如 Crunchbase）可能会超时，但该行仍能通过其他来源完成。使用 `-q` 可隐藏进度，仅查看摘要。

## 调试智能体的操作

添加 `-v`（详细模式）可查看每行的所有智能体步骤，或使用 `--json` 流式输出原始 NDJSON 事件，再通过 `jq` 检查。使用 `--dry-run` 可在不产生任何费用的情况下确认解析后的配置。
