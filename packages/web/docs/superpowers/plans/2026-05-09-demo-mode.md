# DEMO_MODE 实施计划

> <strong>面向智能体式工作进程：</strong>必需的子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans，逐项实施此计划。步骤使用复选框（`- [ ]`）语法进行跟踪。

<strong>目标：</strong>添加一个可选启用的 `DEMO_MODE=1` 环境变量标志，按 IP 强制执行终身 50 行的数据丰富上限，并在达到上限（完全阻止）或请求处理中超出上限（部分截断）时，触发一个可关闭的“这只是演示”模态窗口。

**架构：**`lib/demo-mode/` 中的一个功能标志、一个 Turso（libSQL/SQLite）表 + 事务性 `BEGIN IMMEDIATE` 预留、`POST /api/enrich` 顶部的一个执行点、一种新的 SSE 事件类型（`quota_partial`），以及一个由 `useEnrichment` Hook 状态驱动的新客户端模态窗口。如果无法访问 Turso，则采用失败关闭策略。

<strong>技术栈：</strong>Next.js 16.2.2（App Router、Route Handlers）、TypeScript、`@libsql/client`、Framer Motion、Tailwind CSS 4。**以下所有路径和命令的工作目录：`/home/meirk/BrightAI/Demos/open-enrich/open-enrich/`**（内部 `open-enrich` git 仓库）。路径别名 `@/*` 映射到该目录。本计划中的所有文件路径均相对于该工作目录。

**规范参考：**[docs/superpowers/specs/2026-05-09-demo-mode-design.md](../specs/2026-05-09-demo-mode-design.md)

<strong>重要提示：</strong>本项目使用 Next.js 16，与早期版本相比存在破坏性 API 变更。在做出任何 Next.js 相关决策前，请阅读 [`node_modules/next/dist/docs/`](../../../node_modules/next/dist/docs/)。现有 `app/api/enrich/route.ts` 已遵循 v16 约定，请仿照其风格。

### 任务 3：添加带延迟架构引导的 Turso 客户端单例

- [ ] **步骤 1：编写客户端**

```ts
import { createClient, type Client } from "@libsql/client";

let cached: Client | null = null;
let schemaInitialized = false;

const CREATE_TABLE_SQL = `
  CREATE TABLE IF NOT EXISTS demo_quota (
    ip TEXT PRIMARY KEY,
    rows_used INTEGER NOT NULL DEFAULT 0,
    first_seen_at INTEGER NOT NULL DEFAULT (unixepoch()),
    last_used_at INTEGER NOT NULL DEFAULT (unixepoch())
  )
`;

/**
 * Returns the server-side libSQL/Turso client used by demo-mode quota
 * enforcement. Throws if TURSO_DATABASE_URL or TURSO_AUTH_TOKEN are missing.
 *
 * On first use, lazily creates the demo_quota table (IF NOT EXISTS).
 *
 * Server-only — never import from a client component.
 */
export async function getTursoClient(): Promise<Client> {
  if (cached && schemaInitialized) return cached;

  if (!cached) {
    const url = process.env.TURSO_DATABASE_URL;
    const authToken = process.env.TURSO_AUTH_TOKEN;

    if (!url) {
      throw new Error(
        "DEMO_MODE is enabled but TURSO_DATABASE_URL is not set. See README for setup."
      );
    }
    if (!authToken) {
      throw new Error(
        "DEMO_MODE is enabled but TURSO_AUTH_TOKEN is not set. See README for setup."
      );
    }

    cached = createClient({ url, authToken });
  }

  if (!schemaInitialized) {
    await cached.execute(CREATE_TABLE_SQL);
    schemaInitialized = true;
  }

  return cached;
}
```

### 任务 4：添加配额辅助函数（`getClientIp` + `checkAndReserveQuota`）

**文件：**
- 创建：`lib/demo-mode/quota.ts`

这是核心原子性边界。预留操作在 libSQL `BEGIN IMMEDIATE` 事务内运行，因此来自同一 IP 的并发预留会在数据库写锁级别串行执行。

- [ ] **步骤 1：编写辅助函数**

```ts
import { DEMO_LIFETIME_ROW_LIMIT } from "./config";
import { getTursoClient } from "./turso";

export type QuotaResult =
  | { status: "ok"; granted: number }
  | { status: "partial"; granted: number; requested: number }
  | { status: "blocked" };

/**
 * Read client IP from a Web `Request`. Trusts `x-forwarded-for` (first hop)
 * then `x-real-ip`. If neither is present, returns the literal "unknown" so
 * all header-stripped requests share one bucket and cannot bypass the cap.
 */
export function getClientIp(req: Request): string {
  const xff = req.headers.get("x-forwarded-for");
  if (xff) {
    const first = xff.split(",")[0]?.trim();
    if (first) return first;
  }
  const real = req.headers.get("x-real-ip");
  if (real && real.trim()) return real.trim();
  return "unknown";
}

/**
 * Atomically reserve up to `requestedRows` rows for `ip` against the lifetime
 * cap. Uses a BEGIN IMMEDIATE libSQL transaction to serialize concurrent
 * reservations.
 *
 * Throws on libSQL/network failure — the caller (the API route) catches this
 * and converts it to a 503. We deliberately do NOT fail open: an unreachable
 * quota DB must not allow unlimited demo use.
 */
export async function checkAndReserveQuota(
  ip: string,
  requestedRows: number
): Promise<QuotaResult> {
  const client = await getTursoClient();
  const tx = await client.transaction("write");
  try {
    await tx.execute({
      sql: "INSERT INTO demo_quota (ip) VALUES (?) ON CONFLICT(ip) DO NOTHING",
      args: [ip],
    });

    const sel = await tx.execute({
      sql: "SELECT rows_used FROM demo_quota WHERE ip = ?",
      args: [ip],
    });

    const row = sel.rows[0];
    const rowsUsed = row ? Number(row.rows_used) : 0;
    const remaining = Math.max(DEMO_LIFETIME_ROW_LIMIT - rowsUsed, 0);
    const granted = Math.min(requestedRows, remaining);

    if (granted > 0) {
      await tx.execute({
        sql: "UPDATE demo_quota SET rows_used = rows_used + ?, last_used_at = unixepoch() WHERE ip = ?",
        args: [granted, ip],
      });
    }

    await tx.commit();

    if (granted === 0) return { status: "blocked" };
    if (granted < requestedRows) {
      return { status: "partial", granted, requested: requestedRows };
    }
    return { status: "ok", granted };
  } catch (err) {
    await tx.rollback().catch(() => {});
    throw err;
  }
}
```

```tsx
import { motion, AnimatePresence } from "framer-motion";
import { DEMO_REPO_URL, DEMO_BRIGHTDATA_SIGNUP_URL } from "@/lib/demo-mode/links";

            initial={{ opacity: 0, y: 16, scale: 0.98 }}
            animate={{ opacity: 1, y: 0, scale: 1 }}

                onClick={onClose}
                aria-label="Close"
                className="p-2 rounded-xl text-[rgba(240,242,248,0.35)] hover:text-[#f0f2f8] hover:bg-[rgba(165,180,220,0.06)] transition-all duration-200"

                <a
```

```markdown
## Demo Mode

Set `DEMO_MODE=1` to cap each visitor's lifetime usage at 50 enriched rows
(per IP). When the cap is hit, a dismissible modal explains the limit and
points users to the repo and Bright Data signup.

Required env vars when `DEMO_MODE=1`:

- `TURSO_DATABASE_URL` — your Turso libSQL database URL
- `TURSO_AUTH_TOKEN` — auth token for that database (server-only, never exposed to clients)

Setup:

1. Create a Turso database: `turso db create open-enrich-demo` (or via the Turso dashboard).
2. Get the URL: `turso db show open-enrich-demo --url`
3. Get an auth token: `turso db tokens create open-enrich-demo`
4. Set `DEMO_MODE=1`, `TURSO_DATABASE_URL`, and `TURSO_AUTH_TOKEN` in your deployment env.
5. The `demo_quota` table is created automatically on first quota check; no manual schema step.
6. Confirm your deployment is behind a proxy that sets `x-forwarded-for` (Vercel does by default).

The lifetime cap of 50 lives in `lib/demo-mode/config.ts` (`DEMO_LIFETIME_ROW_LIMIT`).
```

预期结果：
- 全部 5 行均正常执行数据丰富。
